1.  The Overall Flow
1.1  User journey (first launch → rating)
①  Launch as guest  —  app opens straight to Home; onboarding slides show on first launch. Browsing is open — no login needed to look around.
②  Try to participate  —  the moment a guest tries to join/host/chat, login is enforced.
③  Log in  —  phone number → 4-digit OTP by SMS. If an MPIN was set earlier, MPIN replaces OTP on later logins.
④  Set up profile  —  name, interests/sports, skill level, availability. DOB is required to unlock Full access.
⑤  Access level applied  —  Read = browse only · Full = host + join + chat (needs DOB on file). Admin can adjust this.
⑥  (Optional) Get verified  —  submit an identity selfie → admin approves in Verifications → verified badge on profile.
⑦  Discover  —  area-based event feed, category + date filters, popular strip, and search (events / squads / users).
⑧  Join OR Host  —  Join via open (instant), request-approval, or as a whole squad. Host: create event → pick a verified venue or drop a map pin → set capacity + join mode → publishes instantly.
⑨  Check-in on arrival  —  GPS 'destination reached' confirms attendance. PLANNED — not built yet.
⑩  Rate  —  after the event, rate players / host / event. Ratings are live; attendance-gating still TBD.
⑪  Stay connected  —  event & squad chat threads, notifications, and squads that re-fill the same game weekly. Follow/friends + DMs are planned.
1.2  Access gate (the key branch)
Guest → can browse Home & event cards only.  Read access → browse everything, but cannot participate.  Full access → host + join + chat, and requires DOB on file. This DOB requirement is the single most important gate to test.
1.3  Admin flow
①  Log in  —  email + password; per-person invited accounts; every action is audit-logged.
②  Dashboard  —  metric cards (users/events/messages/reports), 30-day growth chart, events-by-status donut, moderation counters.
③  Branch into work  —  Community Management (users · events · venues · categories · squads) · Moderation (chats · reports · appeals · verifications · ratings · broadcast) · System (admins · audit · settings · maintenance).
④  Everything logged  —  the audit log keeps a read-only, actor-attributed history of all admin actions.
Note: Categories are the only entity admins create. Users self-register; events, venues and squads are user-generated and only managed (verified / cancelled / archived) by admins.

3.  Admin Panel — What each page holds
The entire admin panel is LIVE and verified. Every list page also carries the universal controls: search · filters · column toggle · export / export-all · refresh · pagination.
3.1  Access & Dashboard
Page
What it does
Admin login
Email + password; per-person invited accounts; all actions audit-logged.
Roles
Admin + Superadmin. Only Superadmin manages admins. Admins are disabled, never deleted; can't act on own row.
Dashboard
Metric cards (users/events/messages/reports w/ 30-day deltas), growth chart, events-by-status donut, recent-activity feed, moderation counters, refresh + broadcast.

3.2  Community Management
Page
What it does
Users
View profile/activity; set access Read↔Full; suspend/restore; bulk suspend; export. No admin-create (self-register).
Events
View all + statuses; Cancel + Refund; bulk; export. Field-edit undetermined; no create.
Venues
Verify (incl. loose-pin curation); archive; export. Loose-pin backlog observed.
Categories
Full CRUD — the only admin-created entity. Type (Team/Partner), assets, skill-levels toggle, feed order.
Squads
View; archive; show archived; export. No create.

3.3  Moderation
Page
What it does
Chats
View event/squad threads; lock/unlock; export metadata only (not content); no message delete.
Reports
Queue: Open → Reviewed → Actioned/Dismissed; warn/suspend reported user; bulk; export.
Appeals
View → Reject (uphold) or Restore user (reverse); export.
Verifications
Identity-selfie queue → Approve (grant badge) / Reject; export.
Ratings
View; remove abusive/fraudulent ratings; export. (Page unobserved — to confirm.)
Notifications / Broadcast
Compose (title ≤60, body ≤160); audience Everyone / Active-30d; allow-listed deep links; live preview; send; history. No edit/schedule/recall after send.

3.4  System
Page
What it does
Admins
(Superadmin) invite, reset credentials, promote/demote, disable, export.
Audit log
Read-only, timestamped, actor-attributed history of all admin actions.
Settings
Platform config — fees/commissions, cities, feature flags (details TBD).
Maintenance
Ops controls — maintenance mode, cache/reindex (details TBD).
My profile
Edit own account; change password.
